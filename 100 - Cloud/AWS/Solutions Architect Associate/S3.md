# Amazon S3: Buckets, Versioning & Replication

> For foundational S3 concepts (storage classes, lifecycle, security, access policies), see [[100 - Cloud/AWS/Cloud Practitioner/S3|Cloud Practitioner: S3]].

## Buckets

S3 stores objects (files) in **buckets** (directories). Buckets are defined at the **region level**. S3 looks like a global service, but each bucket is created in a specific region.

### Naming

S3 uses a **shared global namespace** by default, meaning bucket names are unique across all regions and all accounts. An **account regional namespace** allows reuse of the same bucket name across regions.

**Naming constraints:**
- No uppercase, no underscores
- Must not be an IP address
- Must start with a lowercase letter or number
- Must not start with the prefix `xn--`
- Must not end with the suffix `-s3alias`

## Versioning

Versioning is enabled at the **bucket level**. When enabled, overwriting the same key creates a new version (1, 2, 3...).

**Best practice:** always enable versioning on buckets.
- Protects against unintended deletes (ability to restore a version)
- Easy rollback to a previous version

**Notes:**
- Files not versioned before enabling versioning get version `null`
- Suspending versioning does **not** delete previous versions; it just stops creating new ones

## Replication

Replication requires **versioning enabled on both source and destination buckets**.

| Type | Description |
|------|-------------|
| **Cross-Region Replication (CRR)** | Replicates to a bucket in a different region |
| **Same-Region Replication (SRR)** | Replicates to a bucket in the same region |

**Key details:**
- Buckets can be in **different AWS accounts**
- Copying is **asynchronous**
- Must give proper **IAM permissions** to S3

**Use cases:**
- **CRR:** compliance, lower latency access, replication across accounts
- **SRR:** log aggregation, live replication between production and test accounts

**Behavior after enabling replication:**
- Only **new objects** are replicated by default
- Existing objects can be replicated using **S3 Batch Replication** (also retries failed replications)
- **Delete markers** from source are optionally replicated to target
- Deletions with a **version ID** are **not** replicated (prevents malicious deletes)
- **No chaining:** if bucket 1 replicates to bucket 2, and bucket 2 replicates to bucket 3, objects from bucket 1 are **not** replicated to bucket 3
